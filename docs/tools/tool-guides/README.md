# Tool guides

> **Who this is for:** IT administrators, platform and security teams, data protection officers, and rollout leads implementing an AI tool their organisation has already chosen.
> **Last reviewed:** 2026-10

These guides help you implement, configure and govern AI tools you have already selected. Each follows the same [template](_template.md): editions, prerequisites, data flow, data handling, admin and identity controls, integration, numbered rollout steps, monitoring, known limitations, cost and exit considerations, with links to official documentation. They are factual and dated. If you have not yet chosen a tool, start with [tool categories](../tool-categories.md) and [choosing tools](../choosing-tools.md).

> **Disclaimer.** These guides are **descriptive, not endorsements**. Inclusion reflects **breadth of organisational use, not preference**, and a product without a guide is not thereby excluded. All vendors are covered with equal depth and tone, and limitations are described as candidly as capabilities. Product names, plans, features and data terms change frequently: **verify before relying on this**, using the vendor's live documentation and your own contract.

## How to use a guide

1. **Read "Verify before relying on this"** and check the "Last verified" date. Guides older than six months are treated as stale under the [editorial standards](../../../CONTRIBUTING.md#3-currency).
2. **Check the editions section against your contract.** Controls often differ by plan.
3. **Work through "Questions to verify with the vendor"** with your account team before rollout.
4. **Use the rollout steps alongside** the [pilot](../../lifecycle/04-pilot.md) and [scale](../../lifecycle/05-scale.md) stages, and record risks with the [AI risk assessment](../../../assessments/ai-risk-assessment.md).
5. **Read "Known limitations" before you communicate** with users, so expectations are realistic.

## Contributing a guide

New guides must use the [template](_template.md) and cover every section. Every product fact needs a citation to official vendor documentation. If you cannot verify a detail, write it as a question to verify with the vendor instead of stating it. Declare any vendor relationship in your pull request. See [CONTRIBUTING.md](../../../CONTRIBUTING.md).
